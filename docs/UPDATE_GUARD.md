# 自动更新的变更保护

2026-11-02。我在保持分流优先级不变的基础上，补充了发布保护和运行验证，没有增加或删除业务规则。

## 自动更新什么时候停止

更新工作流先保存上一份已发布配置，再生成候选、检查离线复现、审计完整源转换和新旧策略差异。`config/update-policy.json` 的初始预算如下，任意一项超限即停止发布：

| 检查项 | 上限（等于上限仍通过） |
| --- | --- |
| 域名边界样本的策略变化 | 2,000 个或全部样本的 0.5% |
| 其中 PROXY → DIRECT | 500 个或全部样本的 0.1% |
| 中国 IPv4 地址集合新增、移除 | 分别不超过旧集合的 5% |
| 中国 IPv6 地址集合新增、移除 | 分别不超过旧集合的 5% |

域名统计是根域名、子域名和边界等合成样本，**不是网站数量，也不是实际访问量**。IP 检查按精确地址集合计算，IPv4/IPv6 分开统计；即使总地址数不变，大批网段替换也会触发保护。

这些阈值是保守的初始审核预算，不代表统计学上的安全线。作为参考，11 月 1 日已完成更新有 16 个 PROXY → DIRECT 边界变化；11 月 2 日更新没有域名策略变化，只有小幅 IP 集合移除，均能通过新预算。小范围上游误分类仍可能在预算内，受保护 AI 规则和原有独立审计继续保留。

超限时，审计 JSON 先保存，再以失败退出；工作流仍上传已有报告，后续发布步骤不执行，订阅保留旧版。报告包含各项变化数量、前 100 个变化样本和触发的阈值。缺失旧配置或非法预算也会失败，不自动放宽限制或重试绕过。

处理失败时应核对上游提交、完整差异和实际业务，再决定修复来源还是通过代码审查调整预算。没有“强制通过”的工作流参数。此保护针对自动更新；具备仓库写权限的人仍能直接提交文件，不能当作分支权限保护。

本地复查：

```sh
python scripts/audit.py --compare /path/to/previous.conf --enforce-changes --output .build/policy-audit.json
```

## 验证与构建开销

- 80 项测试通过，包含真实审计命令对大规模代理转直连的拦截、失败报告保留、IPv4/IPv6 等量替换和阈值边界。
- 离线构建、完整源边界审计、精确 IP 集合检查及跨业务路由/DNS 契约检查继续执行，没有为了提速删减验证。
- 将构建中同一代理列表的重复排序改为一次排序。本机单次 cProfile 对比约 10.9 秒 → 7.2 秒；这是局部测量，不是整个 CI 或客户端性能承诺。
- 与本轮开始时的 `6aafdee` 相比，`dist/Shadowrocket.conf`、源快照和冲突报告逐字节不变；`manifest.json` 仅更新生成器摘要。首次检查因摘要尚未同步而失败，重新离线生成后复现和全部测试通过。
- 未测得长期客户端内存、耗电或启动开销，配置文件大小不能直接等同于运行内存。
