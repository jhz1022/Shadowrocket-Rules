# 客户端检查

当前配置按服务器目标 IP 分流，详见 [IP_ROUTING.md](IP_ROUTING.md)。不要再用“某个域名必须直连”作为验收标准。

1. 更新并启用配置，全局路由选「配置」，选择自己的节点。更换解析模式后重连 VPN，并重新打开测试应用，避免复用旧连接。
2. 打开小火箭「数据」中的连接记录，查看目标 IP、命中规则和策略。大陆目标应命中 IP-CIDR / IP-CIDR6 DIRECT，其余应命中 FINAL PROXY。局域网与 DNS 保护另有规则。
3. 对照国内和境外目标的出口。例如 us.ip111.cn 只有在实际解析到境外地址时才应代理；不为检测站强制设置结果。
4. 分别检查日常使用的浏览器、Claude、微信、Apple 和 Steam。CDN 可能随网络和时间改变地址；HTTP 根路径响应不等于登录、下载、语音全部正常。
5. iPhone 开启「隧道 → 包括所有网络」并重连，在 Wi-Fi、蜂窝及网络切换后分别检查连接与出口。IPv6-only 请求失败并不能单独证明所有 IPv6 流量都不会绕过。

默认采用 IPv4 兼容模式。系统 IPv6、应用自带 DNS、局域网旁路、Private Relay 和其他 VPN 可能改变路径，不能只凭网页上的一个出口 IP 宣称零泄漏。

公网域名经代理访问加密 DNS，节点故障可能同时影响新的域名解析；国内网站也可能解析到境外 CDN，随后使用代理。先核对实际目的地址，再判断是否为规则错误。

本地脚本 `scripts/probe_client_services.py` 可进行公开 HTTP/NTP 探测，并按实际目标 IP 给出静态预期；最终策略仍以原生连接记录为准。`probe_client_dns.py` 默认检查真实 A 记录和端口 53 拒绝兜底，也可用 `--resolution success` 检查 TXT 正向解析；真实 IP 答案本身不能证明 DNS 出口，需结合原生记录。
